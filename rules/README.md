# 角色与规则总入口

更新：2026-11-05。本目录回答“谁负责什么、遇到问题找谁、规则在哪里改”。工具步骤查[文档地图](../docs/README.md)，真实能力查[05](../docs/05-validation.md)。

**连接器增加能力上限，不建立刻板流程。** 当前接手者在授权内负责到底，角色表示可承担的责任，不是只有该角色才有资格做的事。DSH可独立完成任务；确需协作才启用委派、技术问答或复核，不以任务“复杂”自动要求双人参加。

## 规则结构

| 文件 | 用途 | 适用对象 |
|---|---|---|
| [roles/codex.md](roles/codex.md) | 承担任务时的技术责任；被邀请协助时的规划与复核 | Codex，不是全部任务的必经审批者 |
| [roles/dsh.md](roles/dsh.md) | 独立规划、实现、验证、收尾；按需协作 | DSH独立或受委派工作均适用 |
| [interaction.md](interaction.md) | 自主推进、询问、暂停、批准与反馈约定；现有configure发送入口 | 指定DSH原生会话 |
| [development.md](development.md) | **旧固定fixture专用规则**，含当时目录和工具限制 | 旧实验工作区，不用于普通项目 |
| [prompts/dsh-independent.md](prompts/dsh-independent.md) | 可直接发送的独立工作文本，附当前Tavern边界 | 可选，不是所有任务必须填写的模板 |

总体工作流在[01](../docs/01-workflow.md)。连接器不额外设置长期主策划会话；如项目已有主策划或设计顾问，由其核对设计一致性，Codex无需让其转述全部技术任务。

成果报告不等于Git提交。获准提交后，任何实际接手者都可核对依赖、归属和暂存范围并实施；不能因为部分改动由另一个AI完成就拒绝。需要包含未获授权的其他成果时，提出准确范围请求补充授权，不猜测扩大许可，也不把二进制文件不能逐行暂存说成绝对无法整理。

权限不足应提出准确申请，不把“不自行扩权”误作“不准申请”。同范围业务授权不重复问，原生执行尽量合并为一次有界任务调用。当前官方只有允许一次，不能伪造任务级允许全部；版本限制和单次宽权限含义见[16](../docs/16-permission-approval.md)。

## 不同内容放在哪里

- **角色职责**：长期责任、判断原则和交付要求，放roles对应文件。
- **协作行为**：何时自主、何时找Codex、何时询问制作人，放interaction。
- **具体任务**：目标、工程、允许修改范围、设计依据、验证条件，放任务工作包，不写成所有项目的永久限制。
- **操作与协议**：命令、JSON、ID、重试和等待步骤，放docs对应专题。
- **系统权限**：由原生客户端、审批和实际沙箱控制，文字规则不授予权限。
- **历史试验**：放history。仍被旧实验代码读取的development保留路径，明确标识用途。
- **任务反思**：放[reflections](../reflections/README.md)，由实际接手者简要写问题、原因、处理、验证与下次改进；不复制证据、不做主观次数评分、不自动升格为永久规则。

分层不增加审批步骤。普通专业工作在已有授权内自主进行；不能把旧实验限制误当所有任务的一律禁止，也不能由AI推定扩大安全边界。

## 如何生效

| 文件 | 实际加载方式 | 修改后的处理 |
|---|---|---|
| AGENTS.md | Codex工程接手入口，本轮增加角色阅读顺序 | 接手者明确读取自己的角色文件，不能假定正在运行的其他聊天自动重读 |
| roles/codex.md | 新增独立角色文档，没有新增系统提示注入代码 | 在原Codex会话明确要求读取，不重建或清空会话 |
| roles/dsh.md | 新增通用角色文档，**没有自动装入全部DSH会话** | 后续获准工作包要求DSH读取，或授权的规则更新消息提供正文；先核对可访问，不扩大文件权限 |
| interaction.md | scripts/session.mjs的configure读取正文发送，触发真实模型和协作方式询问 | 核对准确绑定、当前运行、任务与费用授权后显式发送；改文件不等于发送 |
| development.md | src/workspaces.mjs准备旧fixture时读入新专用profile | 不影响已创建profile，不作为普通项目的通用加载入口 |

configure当前**只读取interaction.md**，不会自动拼入roles。不要为检查而运行它。DSH无法读到角色文档时，由已授权发送者附正文，不假装已读。

本轮只改文件，未发送规则、未改变会话、未触发模型。已有会话仍保留实际收到的版本。今后应用时记录文件版本或SHA256、目标会话和真实回执；“发过/已加载”不代表每次回答均已验证合规。

## 冲突怎么处理

当前制作人授权决定本任务目标与范围；系统和原生权限决定实际执行能力；角色规则规定责任；05说明已实现能力；具体设计依据由项目权威文档决定。历史只解释当时事实。

发现现行文件不一致，核对源码、任务授权和原始证据再修正，不能自行选更宽权限。影响产品目标、设计权威或安全范围的真实冲突才暂停受影响部分，提出具体问题；独立安全工作继续。
