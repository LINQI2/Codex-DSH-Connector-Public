# 12 当前接入路线：优先官方网页服务

2026-11-05说明：本页的创建Host/会话及回收步骤描述旧限定文件试验。已有项目优先连接用户创建的原生会话，不必新建临时Host，也不每项任务都回收整个客户端；日常步骤以[13](13-daily-workspaces.md)为准。

已按制作人决定采用蓝色风车同样的Web接入方式。不是另造网页，仍使用DSH官方客户端。

## 工作流程

1. 明确工作目录、权限和任务范围；保留原只读聊天。
2. 通过官方workspace/create登记工作区，session/create带workspaceId创建会话，记录真实Session ID。
3. 先在官方客户端确认能找到会话，再通过session/prompt发送明确任务。
4. 客户端显示DSH公开消息、编辑和工具过程；连接器保留原始回执，不替代客户端。
5. 用实际文件和工具退出码核验结果。结束后关闭自有执行Host并回收临时权限。

本轮真实验证：同一原生页面无需刷新显示指令与结果，文件实际修改、3项测试通过。见[截图与验收](../history/2026-10-31-web-file-route/ACCEPTANCE.md)。原先“SDK任务在网页找不到”的缺口通过改用Web创建新任务解决；没有把旧SDK会话伪装为已迁移。

## 当前边界

当时蓝色风车保持只读。为隔离限定可写权限，该次试验使用独立临时官方Web Host/profile；这是相同API，不是SDK双路线。试验结束后已关闭并回收权限；当前一键入口打开原官方Host，具体会话和权限由用户选择，不强制进入蓝色风车。

现已接入限定目录的日常入口，见[日常委派操作](13-daily-workspaces.md)。原报告中的“未接入”是当时阶段状态。不能说任意项目已开放。原生轨迹逐项查看、中途补充与停止的文件任务场景仍需制作人实际体验或专项回归。

## 代码与配置入口

- scripts/web-file-validation.mjs：本轮一次性真实Web验证，含创建、浏览器确认、一次发送、状态和结果观察。已有记录拒绝重跑，不是生产派发命令。
- scripts/file-task-acl.ps1：固定两个授权目录的快照与恢复；EvidenceSet区分SDK旧证据和本轮Web证据，不覆写旧快照。resume-cleanup只续接已存在的恢复记录。
- .runtime/web-file-task-evidence：本机私有原始历史、权限快照、恢复回执与归档配置，不整包外发。
- 原SDK脚本和报告留作历史，不删除，不作为后续默认入口。

普通工具或模型结束不等于测试成功，accepted不等于完成；未知投递先核对，不盲重发。Windows官方沙箱仍主要约束写入，不宣称完整读/网络隔离。
