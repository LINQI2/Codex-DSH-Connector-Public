# 15 Codex 主开发直接委派命令

2026-11-05。复用src/dispatch.mjs与原官方DSH接口，不另建执行框架。新命令npm run delegate，源码scripts/delegate.mjs、src/delegate.mjs。无需Computer Use，不把任务交给制作人复制发送。

本页只适用主动选择Codex委派的情况。DSH独立工作不必调用该命令，也不强制Codex核验。当前CLI发送文本仍固定附带“不Commit/Push”，这是现有实现的限制，本轮文档优化没有修改它；有Git任务须核对真实发送内容与当前明确授权，不能声称已经支持按任务生成Git许可。通用角色规则不自动扩大旧工作包的提交范围。

## 前置条件

2026-11-11修正：原生项目内开发或用户已手动选择的完整访问（danger-full-access/full-access）均可通过开发权限检查；不能把完整访问误报为读写未确认或要求切回。只读、缺失和未知自定义权限仍不推断可写。此修正不切换权限，也不增加业务授权。

制作人已批准具体工作包和调用费用；绑定已允许且模式为autonomous；准确DSH会话为项目读写，工程空闲，无未知投递。CLI只核对配置条件，不能证明制作人授权，因此主开发必须依据真实授权上下文判断。confirm-new或暂停时拒绝，不伪造人工批准。调用者ID参数用于防错，不是密码学身份认证；同用户恶意进程不在本地工具威胁模型之外被此机制阻止。

先读[安全诊断](14-ai-handoff.md)，运行diagnose。再在连接器根目录执行下面的预览（不会发模型消息）：

```powershell
npm run delegate -- --codex-thread 00000000-0000-4000-8000-000000000001 --workspace <本地路径> --task-file <本地路径> --id initialworld-20261105-dispatch01
```

仅在已有工作包授权、制作人未暂停、确认同一任务尚未手工发送后，加 --send 执行实际投递。保持相同--id；编号必须16至80位字母数字或短横线。预览只检查本地绑定与文件，不检查模型实际运行；发送才实际读取原生权限、运行与同工程占用。

task-file必须是绑定工程内真实.md文件，防止符号链接逃逸；向DSH发送读取该工作包的明确指令，不拼入任意Shell。任务正文和许可范围以已有文档/真实批准为准；命令本身不授权新增范围、ACL、标签或正式工程。默认不读工作包内容、不执行模型、不创建投递记录。

## 受理、错误和恢复

受理后优先调用只读MCP `wait_dsh_feedback`，替代反复status；详见[17反馈等待](17-feedback-wait.md)。工具默认最多等15分钟，仅反馈/异常/到时返回；不改DSH执行上限。当前对话若未发现工具，先重载MCP，不把反复Shell短轮询描述为无额度等待。

- accepted只证明接口受理；查看官方DSH原生过程，并用npm run status和工作包指定的证据文件复核。
- 记录submittedVia=planner-cli，与producer-ui分开；明确委派不是冒充制作人重新批准。
- 稳定编号已有记录则拒绝。attempted/unknown或答复投递未知时，不能换编号绕过。
- 文件锁保证此runtime内CLI和页面不同时投递；进程崩溃遗留锁时diagnose提示，维护核对前不自动删除。
- CLI错误仅输出分类说明，不外泄认证、回执全文或原生异常。出现退出码2先核对，不能无限重试。
- 来源绑定在发送前重新检查版本与门禁；不替用户改模式或切权限。

## 不包含

不是常驻调度器，不自动监听全部聊天，不自动唤醒空闲Codex；一对多和成果自动交回仍未完整实现。并发锁只覆盖本项目runtime的任务派发，不能约束用户在DSH客户端直接提交，也不宣称跨多份连接器/收件箱答复的全局事务。未知投递仍须人工或明确技术核对。

该功能最初验收只含模拟投递和真实工作包预览，当时主开发暂停，未发送任务。这是历史时点，不代表当前仍暂停；当前执行查原任务和投递记录。后续发送/续接按已有授权与实际暂停指示处理，保留真实回执，不为文档核对另开模型任务。
