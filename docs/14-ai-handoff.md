# 14 新 Codex 的安全状态核对入口

2026-11-05。用于规划者接手，不要求Computer Use，不改变会话、权限或任务。

## 命令

在 <本地路径> 中执行 npm run diagnose。针对当前接手任务必须带预期目标：

```powershell
npm run diagnose -- --codex-thread 00000000-0000-4000-8000-000000000001 --workspace <本地路径>
```

其他任务使用自己的真实会话ID与工程，不照搬例子。可追加 --json 获取结构化摘要。退出码2表示检查异常或未完成，不表示模型任务失败；退出码0只证明这些连接核对未发现异常，不是实施授权或执行验收。

## 隐私与检查范围

内部读取私有配置、绑定、收件箱及投递状态；只输出双方ID、工程、模式、DSH身份/权限/运行状态、待答与未知投递计数。不输出认证URL、Cookie、原始错误、私有配置全文、问题/任务正文或聊天记录。RPC仅session/list，不发prompt、不写记录、不启动Host、不改ACL或绑定。源码为scripts/diagnose.mjs、src/diagnose.mjs。

“不直接读取.runtime和config/local.json”不等于禁止该封装命令。新提示词需明确允许它，不要用浏览器猜测状态。若宿主限制回环查询，按实际工具审批处理，不切未知Host或扩大工程权限。

## 按结果继续

- 身份匹配、空闲、无未知投递：结束连接现场核对，继续审计与方案。
- 只读：可继续审计。实施修改前请制作人在该DSH原生会话选择项目内开发，并确认任务授权，不代选。
- 绑定错：让用户核对选择，不自动改绑。
- 工程忙或未知投递：先核对原执行/requestId，不重复派发。
- 有待答技术问题：活动Codex可使用npm run inbox读取真实问题；不批量外发内容。
- 不检查Unity连接、Play状态、Shell初始化、设计或测试结果，这些按任务另行核对。

## 不混淆状态入口与完整协作

diagnose仅补状态入口；同日已新增主开发npm run delegate明确发送命令，见[15](15-planner-delegation.md)，不再要求制作人手工提交每个自主委派。默认预览、加--send才真正发送，工作包真实授权与暂停仍须遵守。不能把诊断或configure说成发送，也不意味着完整自动路由已部署。成果仍需实际读取核验。见[05](05-validation.md)和[09](09-native-routing.md)。
