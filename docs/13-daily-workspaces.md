# 13 日常项目、会话与权限

现行操作，更新于 2026-11-10。旧实验步骤不再是日常主流程。能力总表见[05 当前状态](05-validation.md)。

## 日常最快使用

- 已经配置好的连接：打开连接器，沿用已保存的双方会话，直接在Codex安排已授权任务。不必重新添加目录、保存、检查、允许，也不必阅读源码或做试运行。AI发送前仍核对实际身份、忙状态及未知投递。
- 新目录：点“添加工作目录”，填路径；选择双方会话并保存、检查、允许一次。以后复用。只是添加同目录新会话则刷新列表即可。
- AI第一次接手：读AGENTS入口，运行一次diagnose；正常后推进真实任务。需要委派时查15的命令格式，不遍历脚本或重查整套架构。排错才读相关源码。

这不是固定几分钟的初始化流程。首次启动需等原生服务就绪，已有服务应复用；登录、网络/代理、原生Host不可用等须具体报错。启动器每服务45秒是故障判定上限，不是每次固定等待。超过正常响应时间应定位具体步骤，不无限准备。

以下是需要连接器协作时的操作，不是所有研发的必经流程。DSH可在原生会话独立接手、规划、验证与收尾，不必先选Codex、建绑定或等待其复审。确需委派/技术问答时才配置连接，实际工程和Git授权仍须遵守。

## 选择两个原生会话

Codex列表优先显示客户端保存的会话名称，而非首条消息形成的旧标题。客户端改名后，回连接器点“刷新列表”同步；不会修改原生会话名称或改变绑定身份。旧版索引没有名称字段时才回退旧标题。列表仍按实际工作目录分组，目录名称不等于客户端自定义项目名称。

1. 双击根目录“打开连接器.cmd”，打开官方 DSH 网页和连接设置页。
2. 连接页左右分别是 Codex 规划者与 DSH 执行者。按实际工作目录展开并选择会话；双方目录可以不同，但必须核对任务实际执行目录。
3. 填连接名称、选择协作方式，保存，检查双方身份，再“允许按此连接发送”。保存和允许都不会自动发消息、启动模型或扩大权限。
4. 日常讨论、查看公开回复、工具、错误、中途补充和停止，在各自原生客户端进行。连接器不会自动转发每句话。
5. 更换选择须重新保存和核对；暂停或断开保留原会话和历史，不终止正在运行的任务。

连接器一次管理一对绑定。持续自动接收、空闲 Codex 自动答复及成果自动回传核验尚未完整接通；不要派发后假定对方已接收或已经开始。

## 已登记的工作目录

| 目录 | 用途与边界 |
|---|---|
| 原 workspace | 原问答验证来源；“蓝色风车”是历史验证会话，不是每项任务都要使用的固定入口 |
| fixtures/file-task-20261031 | 旧限定文件试验；只有这项支持本连接器自动准备、关闭与权限回收 |
| <已有工程路径> | 已登记的已有项目；沿用用户原生会话权限，不代建环境、不自动授予写入 |
| <本地路径> | 2026-11-05 按用户要求登记；不是正式 RRPG；登记不等于本次游戏修改授权 |

目录只是原生会话的归属，不需要为每个项目新建沙箱平台。新目录直接用网页“添加工作目录”登记，保存于.runtime/registered-projects.json，即刻刷新，无需维护者修改配置或重启服务。config/local.json的connectedProjects保留兼容。登记不触发ACL准备、复制认证或创建替代会话。

DSH 候选来自当前 Host 的官方侧栏，过滤空白、归档、目录不匹配会话。新建空白会话可能尚不显示；在 DSH 中发送首条实际消息后刷新连接页。不要删除旧记录来制造列表一致。其他 home 的桌面会话不保证自动出现。

Codex候选在刷新时只读查询本机state_5.sqlite索引；不是官方桌面实时API。范围为既有Codex目录与已登记项目，排除归档、子Agent与内部审查。仅取名称、ID和目录，不读正文。索引不兼容/不可读明确报错；不拿旧清单冒充刷新成功。不自动发现远程Host或其他Codex home。

## 自己添加、移出和更换会话

- 新建：在Codex或DSH原生客户端新建，再回连接器点击“刷新列表”；DSH空白会话仍需先发首条实际消息。
- 移出：点会话旁“移出列表”并确认。只隐藏连接器候选，客户端会话、历史、执行和权限不变。当前绑定须先断开才能移出。
- 恢复：点击对应侧“恢复已移出会话”，选择此前移出的会话。没有隐藏项时不显示空下拉框或提交按钮，明确指引返回主列表选择；新建仍在原生客户端完成后刷新，不会代建或触发模型。
- 更换：选择新的双方会话，再保存、检查、允许。发现新会话不会自动替换绑定。
- 记录：隐藏名单在私有.runtime/session-visibility.json，正常重启保留。客户端已删除/归档或已移出登记目录的会话不会因“恢复”被重建。

## 怎样看和调整权限

在DSH原生输入框下方点击当前权限名称，可选择“仅查看（只读）”“项目内开发”“完整访问（会话级）”。完整访问会出现官方确认，勾选知悉后由用户启用；取消不改变权限。它持续到手动切回，文件沙箱不再限制普通用户能访问的工程外路径，不是管理员，也不代表所有业务操作获准。默认仍只读，连接器不替用户切换。配置在officialHost.home/profiles/probe/cordis.patch.yml。

完整访问与每次工具弹出的“允许一次”是不同入口。选择完整访问后，正常文件/Git操作无需再逐条请求更宽文件沙箱；明确业务授权、其他工具或系统要求的确认仍适用，不承诺所有操作永远免批。切回“项目内开发”即可恢复该会话的工作区文件限制。

会话名后的小标签：
- DSH：刷新时读取当前原生 preset。
- Codex：匹配 Thread 的最近本机权限记录，标为“记录”，悬停看时间；不是实时客户端设置。应在 Codex 原生客户端修改权限。
- 无法读取：显示未读取或待核对，不猜测为只读。

选择项目内开发不证明 Shell 已可运行，也不替代任务范围授权。新目录如需 ACL、低完整性标签或管理员等额外变更，应停止受影响操作，先说明范围、风险和恢复方法取得授权。旧 fixture 的权限修复脚本不能用于 Pilot。

2026-11-05例外已单独批准：维护端在Pilot根使用官方修复并验证一次真实Shell退出0。当前Pilot及日常profile审批为ask，必要时先询问；不扩大到其他目录或自动切Full Access。此修复不是将旧fixture脚本改成通用权限工具，详见[16](16-permission-approval.md)。

## 明确发送和协作方式

主开发应依据已确认目标选择明确委派，而不是转发全部聊天。独立无冲突包可规划并行，但本连接器尚无完整一对多路由。

当前直发与预览确认面板在“专业维护与旧验证工具”中，是保留的接口验收入口，不应要求制作人用它代替正常聊天。该面板提交前确认；不能据此说所有原生委派都必须制作人逐包批准。自主模式不要求普通技术工作逐步审批；新委派先确认模式需确认；这些也不等于完整自动编排已部署。

工具受理、模型结束、文件存在均不等于验证通过。未知投递先核对原 Session/requestId，不能换编号重发。技术问答的当前操作与等待方见[09 路由](09-native-routing.md)。

## 旧实验维护区

只有固定 fixture 才使用“准备所选工作区 → 创建空白会话 → 明确发送 → 关闭开发工作区并回收权限”。它创建专用官方 Web profile/Host，保留每轮快照；不是新项目日常接入的必经步骤。

关闭浏览器不停止模型；先在原生客户端停止并核对修改。关闭工作区要求执行空闲，回收失败则保留证据。进程意外退出后未核实回收前不自动重开写权限；维护者核对进程和原快照，不手工改状态绕过。详见[限定权限](11-file-task-permission.md)。

## 到哪里查文件

| 文件 | 职责 |
|---|---|
| config/local.json | 私有 connectedProjects、官方 Host 与基础连接；长驻设置页启动时加载，修改后需正常重载设置服务 |
| src/workspaces.mjs | 现有目录登记、候选发现、旧 fixture 生命周期 |
| src/sidebar-sessions.mjs | 官方侧栏顺序、空白与归档过滤 |
| src/session-catalog.mjs | Codex本地索引只读发现、连接器隐藏名单；没有原生删除API |
| src/permission-view.mjs | 小权限标签与来源说明 |
| src/dispatch.mjs | 明确发送、投递记录、unknown 防重复 |
| src/routing.mjs、src/mailbox.mjs | 按绑定选择 Host、技术提问与答复关联 |
| rules/interaction.md | configure 显式发送的协作规则，会触发模型 |
| rules/development.md | 旧 fixture 准备时装入专用 profile，不自动装入所有新项目会话 |
| scripts/file-task-acl.ps1 | 固定 fixture/专用临时目录的快照及回收，不是通用授权入口 |

修改规则文件不会自动覆盖已有对话。历史消息、认证、投递证据和未知状态不得为更新说明而删除。

# 新工作目录里的会话如何加入（2026-11-07更新）

连接页顶部点“添加工作目录” → 填完整路径 → 确认添加 → 在主列表选会话。无需找维护者改配置。登记只保存在连接器.runtime/registered-projects.json，不修改项目、客户端会话或权限；同目录重复登记会去重。取消不保存，错误路径会在面板内提示。

同一已登记目录中新建会话，点“刷新列表”即可。两侧“恢复已移出会话”仅恢复原先隐藏的条目，不负责登记新目录。DSH空白会话需先发送首条消息，且必须属于连接器当前原生Host；不同Host/home的会话不能仅靠路径读取，未发现不代表已删除。
