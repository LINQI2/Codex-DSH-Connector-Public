# 07 后续工作与边界

更新：2026-11-05。本页只列未完成事项，已实现能力统一查[05](05-validation.md)，不再把历史计划当成待开发清单。

## 优先级

| 优先级 | 下一项 | 怎样才算通过 |
|---|---|---|
| 1 | 原Codex会话发现并实际使用反馈等待工具 | 不重建会话；在正常获准任务中验证收到技术问题/结束反馈再处理，区别程序模拟与真实事件 |
| 2 | 验证15分钟客户端等待、取消和续等 | 单次工具保持等待，取消只结束监听；到时不误判任务失败、不重发 |
| 3 | 正常任务完整交接与核验 | 用已有delegate、inbox/answer和明确证据文件完成真实工作包；受理与完成分开记录 |
| 4 | 按需评估回合结束后的接收与唤醒 | 有当前客户端支持证据、明确启停和去重；不用模型定时轮询冒充事件唤醒 |
| 后续单独评审 | 一对多执行与更完整并行 | 用户当前已推迟；不自行扩展槽位、建新会话或调度平台 |

上述真实验证依当前任务和费用授权开展，不因写进计划自动获得调用或游戏写入权限。角色文件已整理，不因文件存在宣称已发送所有会话；加载见[规则入口](../rules/README.md)。

## 不重复建设

会话发现和列表管理、权限菜单及标签、明确委派CLI、DSH技术问答、只读反馈等待工具均已有实现。优先补真实使用和反馈链验证，不再从头开发同名入口。

不顺带建设完整聊天客户端、通用沙箱、Worktree平台或全自动崩溃恢复。Unity和正式RRPG接入按独立任务授权，不借旧Studio验收结果宣布本连接器通过。

改动前读实际源码与范围 → 备份 → 实施及相应无模型检查 → 获授权时做有界真实验证 → 更新专题、05总表和日期化history。无变化时不重复模型检查；每项报告标明真实、模拟或未验证。
