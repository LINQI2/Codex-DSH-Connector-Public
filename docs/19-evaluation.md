# 19 使用成本与时间评估

更新：2026-11-06。已支持 Codex 与 DSH 的时间、用量和可选费用估算分开查看；支持任一方独立工作或双方协作。实际单任务现金账单没有可靠来源时显示具体原因，不把估算冒充实际费用。

## 从哪里打开

打开连接器，在会话连接页顶部点击“成本与时间评估”。过程和对话继续在官方客户端查看，这里只查看统计。

## 怎样开始统计

- **通过连接器发送的新委派**：保存 DSH 发送前的原生序号和用量基线，同时保存绑定的 Codex 身份；服务在下一次采集周期自动登记并尝试关联 Codex，从读取时建立 Codex 基线。此前规划用量不回填。若要覆盖规划阶段，请在讨论前登记双方，通常在 30 秒内可见。统计故障不阻止派发。
- **直接在原生客户端工作**：先展开“登记原生客户端中的任务”，填写短名称，选择 DSH 独立、Codex 独立或双方协作，再选择相应会话并确认。Codex 独立统计不依赖 DSH 在线。登记不会发送任务、创建会话或改变权限。
- **已有统计补充 Codex**：任务详情点“选择或补充Codex会话”，选择后确认，从当前建立新基线。已有 DSH 数据保留；同一 Codex 会话不能同时计入两个活跃任务。
- 已在进行中的任务也可登记，但只能得到结算差值：可能包含登记前启动、登记后才结算的调用，会标部分观察。旧历史不会自动批量补算；没有可靠起点就不猜。

同一会话同时只能归属一个采集任务。当前采集范围不自动理解消息语义，避免在区间内混聊其他任务。登记目录和任务都不授予业务或文件权限。

## 怎样读账单

| 页面内容 | 实际含义 |
|---|---|
| 已测 Token | Codex、DSH 各自累计记录的区间差值。Codex 缓存是输入子集，先拆分；DSH 四桶已互斥。推理均不重复计入输出 |
| 观察历时 | 从登记/委派到当前或手动结束统计；包含观察窗口之间的空档，不是纯执行时间 |
| 有证据的执行时间 | 两栏分别取各自原生回合区间与登记窗口的交集、并集。Codex读取task_started/task_complete的毫秒耗时，DSH读取turn事件。包含工具/等待，不是纯推理时间；不能把两栏直接相加当协作墙钟耗时 |
| 采集中 | 统计观察开启；各方是否运行按最近只读记录分别显示时间，不冒称实时心跳 |
| 本轮观察结束 | DSH 回合结束冻结该 DSH 区间；Codex 会跨回合保持采集，以覆盖后续规划/复核，直到结束本任务统计；不等于任务验收通过 |
| 实际费用来源 | 当前本地 Codex 用量事件不含单任务现金金额；DSH 用量投影也不含金额。已安装DSH的account/getBalance是账户余额，不能当任务费用。订阅用量与现金账单另行区分 |
| 数据不完整 | 可能有断线、缺失字段、计数回退或截断历史；保留事实，不推算成精确数字 |

账单中“继续采集同一任务”建立下一段基线，不发送任何开发指令；请仍通过原生客户端或已有委派入口让 AI 继续。中间没有观察的用量不会补加。

任务不再需要观察时点击“结束本任务统计”，最后核对双方用量并封存；不会停止任何一方，也不会批准成果。封存后如有新工作请新登记任务。DSH回合自然结束只冻结DSH区间，仍可继续采集同一任务；正在采集的Codex不重复建立基线。

若在AI仍运行时封存，会提示尚未结算调用可能未计入，不能当完整费用。DSH结束采样若已出现后续原生记录，也会标注归属待核对。

页面每 15 秒刷新本地账本；采集器每 30 秒核对双方活跃窗口，DSH结束事件到达时也核对。Codex通过只读索引定位已选择、未归档的准确会话，只增量读取原生JSONL并保留计量/时间，不保留消息正文或推理；不是重新启动App Server接管会话。空账本不读取原生事件，不唤醒模型。

## 费用估算是可选项

在任务详情展开“设置估算单价”，先选“Codex”或“DSH”，分别输入说明、币种和四项每百万 Token 单价。两边价格、币种与历史独立，不把一个价格套给双方。只有确认该工具所采集窗口适用同一计价方式时才设置；模型/渠道混用不能用一个价格假装精确。

官方[Codex计费说明](https://learn.chatgpt.com/docs/pricing?codex-pricing-plans=individual)区分订阅用量、购买额度及API计费；不能把API单价计算的金额称为订阅任务实际费用。官方[App Server说明](https://learn.chatgpt.com/docs/app-server)中的账户Token日汇总也不等于逐任务现金账单。本模块不为获取账单而读取或外发认证、不新增付费调用；若将来有可核对的逐任务账单来源，再接实际费用，不用账户余额差猜。

估算单价变更留历史。数据缺失或覆盖异常时不提供完整费用估算。没有可信单价保持未设置即可；首版没有账单账户连接、扣费、额度上限或预算自动停止功能。

## 反思与验证

返修、人工介入及原因由实际接手 AI 写[任务反思](../reflections/README.md)，不做次数统计或自动评分。实际成果和真实测试复用原生会话、项目交付与证据，本页面不新增人工验收流程。下一步可自然观察 3～5 个已授权任务再评价数据质量，不为统计另行付费跑任务。

## 数据、备份与故障

- 私有账本：`.runtime/evaluation/evaluation.sqlite`，SQLite WAL 模式，已由现有忽略规则排除 Git。新增Codex表，旧DSH表与记录保留；原绑定、投递和官方会话不迁移到此数据库。
- 导出 CSV/JSON 含任务名称、工程目录、会话标识与计量摘要，不含完整聊天、隐藏推理或认证；分享前仍需核对。CSV 对公式前缀做转义。
- 备份时先正常关闭连接设置服务并确认数据库连接退出，再复制评估数据库；不要直接复制正在写入的单个 SQLite 文件当成一致备份。恢复时保留当前账本备份，使用同版本、服务已关闭的备份替换，仅处理评估目录；不覆盖 config、原生 home 或其他 runtime 数据。
- 设置服务关闭不停止 DSH。再次启动时有界读取官方事件窗口并标注跨重启覆盖；缺失历史不隐瞒、不重发任务。原生连接失败按 30 秒周期重连只读观察，不改变 unknown 投递结果。
- 关闭整个连接器的步骤仍见[启动关闭](10-daily-operation.md)。统计模块不可用时，原有连接与任务功能继续使用；无需通过更换会话或扩权修复统计。
