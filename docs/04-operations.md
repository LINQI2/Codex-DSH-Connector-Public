# 04 操作说明

现行说明，2026-11-05。完整日常操作看[13 日常目录](13-daily-workspaces.md)，启动关闭看[10 日常启动](10-daily-operation.md)。

## 制作人怎样用

双击“打开连接器.cmd”，选择并核对双方原生会话。日常在 Codex 和 DSH 原生客户端讨论、查看公开过程或停止任务，不必使用旧蓝色风车会话，也不必先代建实验环境。只讨论时明确“先审查、不实施”。

保存和允许连接不发送消息，不授予文件权限，也不部署自动路由。使用前须有明确任务范围、原生工具能力和实际发送方式。当前不能假定 Codex 闲置时会自动读问题或接收完成结果；需要明确接手方式，见[09 路由](09-native-routing.md)。

## 维护命令

在项目根目录执行：

- npm run open：打开/复用服务及两页，不调用模型。
- npm run services：服务与本地接收登记状态。
- npm run diagnose：安全状态摘要，优先用于新Codex核对绑定、DSH权限与执行；详见[14](14-ai-handoff.md)。不读正文、不调用模型。
- npm run delegate：主开发委派，默认预览；显式--send会调用真实模型，须有现有授权且未暂停，见[15](15-planner-delegation.md)。
- npm run status：按当前绑定读取 DSH 状态与公开回复；无绑定时用基础配置。
- npm run inbox：按当前绑定读取未答技术问题。
- wait_dsh_feedback：Codex只读MCP等待反馈，优先代替循环status；CLI备用为npm run wait-feedback，区别与限制见[17](17-feedback-wait.md)。
- npm run check：语法和文档链接检查，无模型。
- npm test：自动化回归，无模型。
- npm run configure：发送协作规则并触发真实 DSH 模型调用；不是检查命令，不为确认配置而重复运行。
- npm run stop：核对空闲后正常关闭自有服务与旧 fixture 回收，不强杀。

答复命令和真实调用边界详见[09 路由](09-native-routing.md)。旧实验脚本不是正常游戏任务派发入口。

## 常见情况

| 现象 | 含义和下一步 |
|---|---|
| 新目录没显示 | 先查是否登记、是否属于当前官方 Host；有无非空白非归档会话，然后刷新，不重建正常会话 |
| 权限显示“记录” | Codex 最近保存记录，非实时设置；查看时间并在原生客户端核对 |
| running=true | 可能模型、工具或等待用户，结合原生界面，不代表一直在推理 |
| running=false | 没有活跃执行，不等于任务通过 |
| ask_codex 已登记 | 等活动 Codex 明确读问题；当前不保证自动唤醒，不能假称对方已收到 |
| 原生询问未答 | 不代答、不假定批准；说明需要谁做什么，可继续独立授权工作 |
| 发送超时/unknown | 查准确 Session/requestId，不换 ID 重发 |
| Host 失联 | 核对进程和日志，保留错误，不重启旧 Studio、不重建会话 |
| 窗口关闭 | 服务与模型可能继续；停止模型用原生停止，之后核对副作用 |

运行数据不写死进现行文档。原生 home 留原位；不为解决连接问题复制凭据或升级系统权限。
