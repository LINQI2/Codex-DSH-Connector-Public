# 10 日常打开、关闭与查看

双击项目根目录 **打开连接器.cmd**：打开官方 DSH 网页与连接设置页。已有服务复用，不创建会话、不自动发送消息、不调用模型。不需要修改 PowerShell 系统执行策略。

在 DSH 网页选择你实际要使用的项目会话，查看公开回复、原生询问和轨迹；“连接验证与蓝色风车”仅是旧问答会话。设置页选定并核对双方，再允许后续明确发送。“允许发送”不是启动模型，也不是永久自动协作。

关闭标签不会结束服务。双击 **关闭连接器.cmd**，先停用本地自动答复，再检查所有 DSH 会话是否空闲；有执行或待答时拒绝关闭。不强杀，不删除会话、认证和绑定。要停止当前模型先用 DSH 原生停止，再核对文件影响。

当前后台接收关闭。此前 Codex 原生定时唤醒只验收过一次，自动化已删除。打开页面不会恢复模型调用。本地停用按钮不能代替删除 Codex 原生自动化；未来登记定时器时须同时核对 Codex 的自动化管理界面。

## 维护命令

```powershell
npm run open       # 打开两页并复用/启动服务，不调用模型
npm run services   # 核对服务和后台接收状态
npm run status     # 读取当前绑定DSH；无绑定时使用基础配置
npm run stop       # 空闲时关闭本项目拥有的服务
```

已取消旧探针的一小时自动退出。没有安装系统服务或开机启动；进程退出后重新双击打开。进程仍活着但接口失联时不重复拉起，查看私有 `.runtime` 启动日志。复用的旧服务没有本项目控制接口时保留它，不按 PID 强杀。

Windows 偶尔对已退出的旧进程号返回 EPERM（无权访问），不代表需要管理员。启动器会再通过 Windows 进程清单核对：明确不存在才归档失效启动记录并重新启动；清单读取失败或进程仍在则保留现场，不重复拉起。不要手动删除会话、配置或认证来解决启动问题。

控制接口仅接受私有随机地址的准确回环请求，拒绝外部浏览器来源；不是 Windows 安全隔离，不能防御同用户恶意进程。完整启动地址含认证信息，不要分享。
