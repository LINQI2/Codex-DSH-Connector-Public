# 17 等待 DSH 反馈，减少 Codex 重复检查

日常用法更新：2026-11-10。下面先讲操作；后面的安装、协议和历史验收只供维护，不要求每次通读。

## 制作人只需要知道

**Codex把任务交给DSH后，让一个本地“等消息”工具守着。DSH正常工作时，Codex不反复追问；需要答复或本轮结束时，工具才把消息交回Codex。** 制作人仍在DSH原生客户端看执行过程，不需要手动计时、刷新状态或操作监听器。

日常流程：**派发成功 → Codex等待 → DSH自主执行 → Codex收到反馈后处理或核验。** 普通代码/测试问题先由DSH自修；真正需要人的权限或操作，负责人应在会话里明确说明。

15分钟只是一次等待窗口，不是固定先等15分钟：结束、提问或异常会提前返回；到时也不会杀掉DSH。取消等待不停止任务。工具等待本身不调用模型，但Codex发起、处理和续等有开销，不能宣称整段对话免费。

## AI日常速查（读到这里即可）

1. 只有任务已实际受理才等待；预览不算派发成功。
2. 调用已提供的 `wait_dsh_feedback`，填 `codexThreadId`（自己的真实会话ID）和 `workspace`（当前绑定工程路径）；其余用默认值。一次保持等待，不每几秒查询status。
3. 收到技术问题就读inbox并答复；收到原生批准请求就通知真人；本轮结束或空闲就查一次成果，不能把停下来当验收通过。
4. 只是超时且任务仍需继续时，在已有授权和预算内用返回cursor作为afterSeq续等；断线、身份不符或结果未知则核对，不重发任务。

**没有发现工具时**，明确说“此聊天未提供等待工具”，不要反复研究源码或声称监听已开启。按已有维护说明核对安装/重载一次；不能假定另一个工作目录的聊天也自动加载Lab配置。CLI是维护备用入口，若宿主较早返回执行session_id，反复轮询仍有模型开销，不冒称等价于一次MCP等待。不能自动扩权或新建替代会话。

以上只是使用说明，改文档不会让既有聊天自动加载工具，也没有新增后台自动唤醒。需要排错、核对安装或了解现有验收边界时，才读下面内容。

## 技术说明与历史验收（按需阅读）

以下保留2026-11-05实施时的细节与验证边界，不作为每次运行前的准备清单。

## 已经做了什么

- 复用安装版本 DSH 的 `session/follow` 官方流接口，准确核对绑定、Session 和工程路径。
- 开始时最多两次 `session/list` 核对，之后只订阅事件，不循环远程查询。
- 本地程序每秒核对绑定与技术问题收件箱；这是普通文件读取，没有模型调用。
- 普通文本、工具调用、单项测试失败不会逐项返回给 Codex。DSH 可以继续自行修复。
- 当前绑定的待答技术问题、原生批准请求、回合结束、连接变化或断线会返回。默认最长等待15分钟，范围1—900秒；不是 DSH 任务执行上限。
- 取消只结束监听，不中断 DSH，不关闭客户端，不扩大权限，不自动发送或重发任务。

等待程序本身没有模型请求。不能保证整个 Codex 对话“零额度”：发起工具调用、处理返回和有界超时后的续等仍有模型开销。本轮没有测得订阅额度的实际节省百分比。

## 给规划者的使用规则

已授权工作包明确派发且受理后，调用 `wait_dsh_feedback`，参数 codexThreadId 为自己的真实会话ID，workspace 为绑定工程绝对路径。默认 waitSeconds=900。不用循环 status 代替等待。

| 返回 | 应做什么 |
|---|---|
| technical-question | 用 `npm run inbox` 读取真实问题，再裁决、关联答复；问题待处理不应反复等待。原答复入口仍检查DSH已结束提问回合 |
| approval-required | 告诉制作人在 DSH 原生客户端查看批准请求；不能由 Codex 冒充批准 |
| turn-ended | 读取一次状态/明确证据文件并核验；completed不等于游戏任务通过，failed也不能推断具体根因 |
| idle | 当前没有活跃回合；核对交付或待答问题，不能继续无意义等待，也不能重发旧任务 |
| timeout | 此窗口无需处理的新反馈；不判失败、不停止DSH。仍在原授权预算内可带上返回cursor作为afterSeq续等，禁止秒级重复检查或无限续等 |
| disconnected / history-gap / protocol-error | 核对原记录；不重发任务、不猜测终态。历史窗口仅最近20条消息，超出窗口保留“需核对”，不伪造恢复 |
| binding-changed / cancelled | 停止监听；原任务未因此停止。恢复或更换绑定须沿用真实门禁 |

afterSeq用于接续已知序号；不是官方接口的resume参数，本程序在官方开流快照中筛选新增记录。不会把旧turn/end当成新完成。问题未答前仍会返回同一待答ID，持久化去重仍由原Mailbox负责；不是保证只提醒一次的通知服务。

## 维护命令与客户端边界

```powershell
npm run wait-feedback -- --codex-thread 自己的真实会话ID --workspace 已绑定工程绝对路径 --wait-ms 900000
```

命令默认只读、不发模型。CLI回环访问可能被当前执行沙箱拒绝，失败不表示 DSH 故障。只按现有授权使用普通用户宿主；不能为此关闭沙箱或建立无限制Shell。

普通exec较早返回session_id时，再让模型每几秒轮询它，仍有模型开销。因此推荐原生 MCP 一次保持等待。Node REPL的单次await已保持35秒只返回一次；但它在当前环境中直接访问本机Host失败，不作为主要入口。真实stdio MCP访问已通过。

这不是 Codex 回合彻底结束后的自动唤醒，也不是所有自然语言自动路由。当前仅识别已接入 ask_codex 收件箱与原生approval事件；其他原生询问仍以DSH客户端为准。未做15分钟客户端端到端长等待、未新增付费任务来制造真实提问或结束事件。下一次正常授权任务可直接验收，不能先宣称通过。

本轮之前Lab项目配置不存在，新配置仅含connector_feedback_wait。停止使用工具，待监听结束后移除此服务段即可；不要改全局MCP或其他配置。源码可按 `.runtime/feedback-wait-backup` 对应文件恢复，新增文件单独移除。绑定、收件箱、任务记录与DSH原会话无需回滚。验收见[记录](../history/2026-11-05-feedback-wait/ACCEPTANCE.md)。
