# 08 选择并管理双方会话

现行说明，2026-11-05。日常完整步骤见[13 日常目录](13-daily-workspaces.md)，启动故障见[10 日常启动](10-daily-operation.md)。

## 连接操作的含义

1. 左右按目录选择 Codex 规划会话、DSH 执行会话，填写名称和协作方式。
2. 保存：登记双方和版本，不发送消息、不增加权限；更换设置使旧身份检查失效。
3. 检查双方身份：Codex 依据保存的原生目录记录匹配 ID/host/已记录目录，DSH 读取准确 Session/workspace。不等于双向投递已通过。
4. 允许按此连接发送：启用后续明确命令的目标约束，不自动发任务或启动后台路由。
5. 暂停后续发送：保留连接，暂阻后续消息；不停止当前 DSH 执行。
6. 断开：解除本地绑定使用状态，保留原生会话与历史；不是删除会话。

当前绑定由用户选择，以页面实际读取为准。不能在文档中固定成“本次 Codex ↔ 蓝色风车”。

## 候选与权限

- Codex刷新时来自本地只读state_5.sqlite索引，非官方桌面实时API；既有目录记录与connectedProjects确定发现范围，排除归档和内部子Agent。缺失/不兼容如实失败，不能退回旧清单冒称已刷新。
- DSH 来自当前 Host 官方侧栏、仅显示已登记目录的非空白非归档会话；刷新读取，不保证其他 home 的桌面会话可见。
- 两边按各自实际目录分组，不强制同目录。
- DSH 小标签为当前 preset；Codex 标签是最近本机权限记录，不是当前实时权限；未知如实标记。
- 一次一对绑定，未完成一 Codex 多 DSH 的完整路由。不同目录接入不等于并行开发已验收。

两侧“移出列表”有独立确认，只更新连接器隐藏名单；“添加／恢复会话”可重新加入，不改变客户端存在状态。当前绑定需先断开才能移出。新建在原生客户端完成，再点击刷新列表，不调用模型建立替代会话。

## 源码和记录

| 文件 | 职责 |
|---|---|
| web/connections.html | 并列选择、目录分组、标签、状态与反馈 |
| src/connections-server.mjs | 回环 API、来源检查、目标匹配 |
| src/bindings.mjs | 保存、检查、允许、暂停、断开、版本与发送门禁 |
| src/dispatch.mjs | 预览后明确发送，真实投递及未知结果防重复 |
| scripts/session.mjs | status 只读；configure 显式发送规则，真实模型调用 |
| src/mailbox.mjs、src/routing.mjs | 技术问题及关联答复 |
| .runtime/binding.json、binding-audit.jsonl | 私有活动绑定与审计，不手工绕过或删除 |

直发验收面板有预览确认；协作模式也有门禁，但不是系统级拦截原生客户端所有操作，更不能把“允许连接”理解成自动执行。当前验证结论统一见[05 总表](05-validation.md)，不再在本页维护另一份测试计数。
